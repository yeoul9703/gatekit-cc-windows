# gatekit 사용 안내

이 저장소에는 gatekit이 이미 설치되어 있습니다. 별도의 설치 과정이나 터미널
명령 없이, 이 폴더를 Claude Code 앱으로 열기만 하면 바로 사용할 수 있습니다.

## 1. 이 폴더를 Claude 앱에서 열기

Claude Code(데스크톱 앱 또는 CLI)에서 이 저장소의 루트 폴더
(`gpters-24th-gate-kit`, `.claude` 폴더가 있는 바로 그 폴더)를 프로젝트로
엽니다. 폴더를 여는 것만으로 `.claude/settings.json`에 등록된 gatekit의 훅
(hook)들이 자동으로 활성화됩니다. `git clone` 외에 추가로 설치하거나
실행해야 하는 명령은 없습니다.

Python 3.9 이상이 컴퓨터에 설치되어 있어야 합니다 (Windows, Mac 공통). 이미
설치되어 있다면 아무것도 더 할 필요가 없습니다.

## 2. 처음 할 일: `/gatekit:setup`

새 프로젝트에서 gatekit을 쓰기 시작할 때는 채팅창에 다음을 입력하세요.

```
/gatekit:setup
```

`.gatekit/config.json` 설정 파일을 만들고, 기본 작업자(worker)로 쓰이는
`claude` CLI가 잘 동작하는지 확인합니다. 이미 설정이 되어 있다면 그대로
두고 상태만 알려줍니다.

## 3. 쓸 수 있는 명령 목록

모든 명령은 채팅창에 `/gatekit:<이름>` 형태로 입력합니다. 한국어로 말해도
자연스럽게 트리거되지만(예: "기획해줘", "빌드 시작해줘"), 명령을 직접
입력해도 됩니다.

| 명령 | 하는 일 |
|---|---|
| `/gatekit:discover` | 아직 뭘 만들지 못 정했을 때, 대화로 문제를 발굴합니다 |
| `/gatekit:interview` | 아이디어를 PRD(요구사항 정의서)와 아키텍처 문서로 정리합니다 |
| `/gatekit:mockup` | 피그마·HTML·스크린샷을 화면 명세로 바꿉니다 |
| `/gatekit:design` | 참고 사이트나 디자인 프리셋에서 디자인 토큰을 뽑아냅니다 |
| `/gatekit:tasks` | 스펙을 실행 가능한 작업(task) 목록으로 쪼갭니다 |
| `/gatekit:gate` | "언제 끝난 건지"를 코드로 검증 가능한 완료 기준으로 정의합니다 |
| `/gatekit:build` | 작업 목록을 실제로 실행합니다 (게이트가 통과/실패를 판정) |
| `/gatekit:verify` | 완성됐다고 주장하는 것을 독립적으로 재검증합니다 |
| `/gatekit:doctor` | 설치 상태를 점검하고 문제를 진단합니다 |

보통 순서는 `discover`(선택) → `interview` → `mockup`/`design`(선택) →
`tasks` → `gate` → `build` → `verify` 입니다.

## 4. 문제가 생겼을 때

1. 먼저 다음을 실행해 보세요.

   ```
   /gatekit:doctor
   ```

   설치 파일이 빠졌는지, 훅이 제대로 등록되어 있는지, 기본 작업자(`claude`
   CLI)가 응답하는지 등 7가지 항목을 점검하고, 문제가 있으면 고치는 방법을
   함께 보여줍니다.

2. 훅이 조용히 실패한 것 같다면(예: 명령을 입력했는데 아무 반응이 없음)
   다음 로그 파일을 확인하세요.

   ```
   .gatekit/runs/hook-errors.log
   ```

   훅 스크립트가 내부 오류로 실패해도 세션 자체는 절대 깨지지 않도록 설계
   되어 있습니다 — 대신 이 로그 파일에 한 줄씩 원인이 남습니다.

3. 그래도 해결되지 않으면, 이 저장소의 `docs/ARCHITECTURE.md`(설계 문서)를
   참고하거나 이슈를 남겨 주세요.
